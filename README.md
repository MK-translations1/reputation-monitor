# Reputation Monitor

Автоматический мониторинг отзывов о работодателе. Бот два раза в неделю проходит по заданным сайтам с отзывами. Новые отзывы он классифицирует моделью **Jev**, записывает в **Notion** и отправляет письмо HR, если на отзыв нужно реагировать.

Бот — это один Python-скрипт в GitHub Actions. ИИ-агент и платные скраперы (Apify) для работы не нужны.

---

## 1. Как это работает

```
GitHub Actions (вт и пт, 09:00 Киев)
  └─ monitor.py
       1. Notion: загрузить checkpoint источников и ID уже известных отзывов
       2. для каждого источника из config.json:
            скачать страницу  →  HTTP → curl_cffi → Exa (запасной вариант)
            вырезать отзывы   →  LLM (gemini-2.5-flash-lite) даёт границы и поля,
                                 сам текст копируется со страницы дословно
            отбросить старые  →  по ID в Notion и дате (checkpoint − 14 дней)
            классифицировать  →  Jev (typesafe/jev-1.13), при неуверенности — LLM
            записать          →  Company Reputation Monitor
            обновить          →  Monitoring State (checkpoint, только при успехе)
       3. одно уведомление HR (Teams и/или email) со всеми отзывами «Очікує» / «Помилка»
       4. отчёт о запуске → Monitoring Runs + Summary запуска в GitHub
```

### Какие отзывы уходят HR

Уведомление приходит **в Teams** (карточка в канале или чате) и/или **на почту**, смотря что настроено. Если настроено оба канала, уходят оба.

Письмо отправляется только если выполнены **все** условия:

- тип отзыва — **«Робота / HR»**: условия работы, руководство, зарплата, нагрузка, культура, найм, собеседования, увольнение;
- Jev ответил, что **HR нужно отреагировать**;
- отзыв **негативный**, либо **смешанный** с приоритетом «Високий» или «Критичний».

Жалобы на качество переводов, цены, сроки и обслуживание **не отправляются**. Они всё равно записываются в Notion с типом «Послуги / клієнти».

В уведомлении по каждому отзыву есть:
- компания, источник, дата, аудитория, тональность, приоритет, зона риска;
- краткое изложение сути на 2–4 предложения;
- **упоминаются ли HR-отдел, рекрутеры, собеседования/найм или увольнение, и что именно о них сказано**;
- рекомендуемое действие для HR;
- ссылки на запись в Notion и на оригинал отзыва.

### Первый запуск источника

Если по источнику ещё нет строки в Monitoring State, берутся все отзывы со страницы. Отзывы старше 30 дней получают статус алерта «Історичний» и в письмо **не попадают**. В Notion при этом всё равно отмечается `Потрібна дія`, чтобы HR мог их просмотреть.

### Главные поля отзыва

| Поле | Кто заполняет |
|---|---|
| ID відгуку | скрипт: `Автор_ДЖЕРЕЛО_РРРРММДД`. Если автора или даты нет, дописывается хеш текста |
| Аудиторія, Тип відгуку, Тональність, Пріоритет, Зона ризику | Jev |
| Релевантність для HR | выводится из поля «Тип відгуку» |
| Ключові проблеми | LLM, для каждого отзыва: конкретные проблемы, которые называет автор, до 25 слов на украинском; пусто, если жалоб нет. Для отзывов с алертом — развёрнуто: коротко, суть, упоминания HR, рекомендация. Сам отзыв дословно лежит в теле страницы |
| Потрібна дія / Статус алерту / Алерт надіслано | скрипт по правилу из раздела 1 |
| Класифікатор | `Jev`, `Jev + LLM` (Jev был не уверен) или `LLM (fallback)` (Jev недоступен) |
| Автор, Дата публікації, Рейтинг, Посада, Локація | только если это указано на сайте, иначе поле пустое |

## 5. Запуск

**По расписанию:** вторник и пятница, `0 6 * * 2,5` UTC. Летом это 09:00 по Киеву, зимой 08:00. GitHub иногда запускает расписание с опозданием до часа.

**Вручную:** **Actions → Reputation monitor → Run workflow**.
- Флажок *Dry run* включён: страницы скачиваются и классифицируются, но в Notion ничего не записывается и письма не отправляются. Результат виден в *Summary* запуска.
- Флажок выключен: полноценный запуск.
- Флажок *test_email*: перед запуском отправить тестовое письмо на `ALERT_RECIPIENT`, чтобы проверить почту.
- Флажок *backfill*: разово заполнить «Ключові проблеми» у уже существующих записей, где поле пустое (сбор отзывов при этом не запускается).

**Локально:**

```bash
cp .env.example .env      # вписать значения, chmod 600 .env
set -a; source .env; set +a
DRY_RUN=1 python3 monitor.py
```

## 6. Секреты

Хранятся в **Settings → Secrets and variables → Actions**. Значения ключей в этой документации **не записываются, ни сейчас, ни после того, как репозиторий снова станет приватным**. Здесь указано только, какие секреты есть и зачем они нужны.

| Секрет | Обязательный | Где взять |
|---|---|---|
| `OPENROUTER_API_KEY` | да | openrouter.ai → Settings → Keys. Для Jev и LLM |
| `NOTION_TOKEN` | да | notion.so/profile/integrations → Internal Integration Secret (`ntn_…`) |
| `TEAMS_WEBHOOK_URL` | для Teams | адрес webhook из Teams Workflows, см. раздел 6.1. Это секрет: любой, у кого есть адрес, может писать в канал |
| `ALERT_RECIPIENT` | для писем | адрес получателя алертов HR |
| `EXA_API_KEY` | нет | dashboard.exa.ai → API Keys. Запасной способ скачать страницу |
| `RESEND_API_KEY` | для писем | resend.com → API Keys, домен должен быть подтверждён |
| `ALERT_FROM` | нет | отправитель, например `Reputation Monitor <monitoring@домен>` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` | вместо Resend | SMTP почтового ящика |

Если ни Teams, ни почта не настроены, алерты остаются в Notion со статусом «Очікує» и уходят при первом запуске с настроенной почтой.

### 6.1. Как подключить Teams

1. В Teams откройте канал (например, HR) или чат, куда должны приходить алерты.
2. **•••** у названия канала → **Workflows** → шаблон **«Send webhook alerts to a channel»** (или **«Post to a channel when a webhook request is received»**; для чата — **«Send webhook alerts to a chat»**).
3. Назовите workflow `Reputation Monitor`, выберите команду и канал (или чат) → **Add workflow**.
4. Скопируйте показанный **URL** и сохраните его в секрет `TEAMS_WEBHOOK_URL`.
5. Проверка: **Run workflow** с флажком *test_email* → в канал придёт тестовое сообщение.

Workflow работает от имени того, кто его создал. Если этот человек уйдёт из компании, workflow нужно пересоздать.

**Ротация ключа:** создайте новый ключ в сервисе, обновите секрет (`gh secret set NAME -R MK-translations1/reputation-monitor`) и удалите старый ключ.

## 8. Если что-то не работает

| Что видно | Причина и что делать |
|---|---|
| Источник `FAILED`, `HTTP 403` | сайт блокирует ботов. Проверьте, что установлен `curl_cffi`, и добавьте `EXA_API_KEY` |
| `HTTP 401` от Notion | неверный `NOTION_TOKEN` или интеграции не дан доступ к базе |
| `Jev: …` в ошибках, `Класифікатор = LLM (fallback)` | Jev был недоступен, классифицировала LLM. Если так повторяется, проверьте баланс OpenRouter |
| «N відгук(ів) не вдалося вирізати» | LLM неточно указала начало отзыва. Эти отзывы пропускаются и будут обработаны в следующем запуске |
| Письма не приходят, статус «Очікує» | не задан `RESEND_API_KEY`/`SMTP_*` или `ALERT_RECIPIENT` |
| Технический алерт «не працює N запуски поспіль» | обязательный источник не отвечает два запуска подряд. Проверьте адрес и вёрстку сайта |
| Запуск не стартовал: *«recent account payments have failed…»* | закончились минуты Actions или проблема с оплатой: **Settings → Billing** |

### Известные ограничения

- С каждого источника берётся **только первая страница**. При двух запусках в неделю новые отзывы туда попадают, но старый архив из глубины пагинации не собирается.
- DOU показывает дату без года («14 вересня»). Поэтому отзыв того же автора на том же источнике считается уже известным, даже если дата отличается.
- Если отзыв на сайте отредактировали, запись в Notion повторно не обновляется.
